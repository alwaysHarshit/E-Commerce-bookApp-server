# Payment Service Technical Report

## 1. Overview
The **Payment Service** is responsible for managing payment transactions within the BookApp ecosystem. It integrates with **Stripe** to process payments and communicates with the **Order Service** to synchronize payment statuses.

---

## 2. API Endpoints

### 2.1 Create Payment Intent
- **URL:** `POST /api/payments/create-intent`
- **Description:** Initiates a payment process by creating a Stripe Payment Intent.
- **Request Body:** `PaymentRequestDto`
- **Response:** `PaymentIntentResponseDto`

### 2.2 Stripe Webhook
- **URL:** `POST /api/payments/webhook`
- **Description:** Handles asynchronous events from Stripe (e.g., payment success or failure).
- **Request Body:** String (Raw Stripe Payload)
- **Headers:** `Stripe-Signature`
- **Response:** String (Status Message)

### 2.3 Get Payment by Order ID
- **URL:** `GET /api/payments/order/{orderId}`
- **Description:** Fetches payment details associated with a specific order.
- **Response:** `PaymentResponseDto`

### 2.4 Cancel Payment
- **URL:** `POST /api/payments/cancel/{paymentIntentId}`
- **Description:** Cancels an existing Stripe Payment Intent.
- **Response:** String (Status Message)

### 2.5 Get All Payments
- **URL:** `GET /api/payments/all-payments`
- **Description:** Retrieves a paginated list of all payment transactions.
- **Response:** `Page<PaymentResponseDto>`

## 4. Database Objects (Entities)

### 4.1 `Payment` Entity
- **Table Name:** `payments`
- **Description:** Stores record of every payment transaction attempted or completed.

| Column | Type | Description |
| :--- | :--- | :--- |
| `payment_id` | `Long (PK)` | Primary Key, Auto-incremented. |
| `order_id` | `Long` | ID of the associated order. |
| `payment_intent_id`| `String` | Unique ID generated by Stripe. |
| `amount` | `double` | Amount charged. |
| `currency` | `String` | Currency code. |
| `status` | `Enum (String)` | `INITIATED`, `SUCCESS`, `FAILED`, `CANCELED`. |
| `created_at` | `Timestamp` | Record creation time (Automatic). |
| `updated_at` | `Timestamp` | Last record update time (Automatic). |

## 5. Error Handling
The service uses a **Global Exception Handler** to ensure consistent error responses.

### 5.1 Custom Exceptions
- **`PaymentNotFoundException`**: Thrown when a payment record is not found in the database. Returns `404 Not Found`.
- **`StripeServiceException`**: Thrown for any errors interacting with the Stripe SDK or processing webhooks. Returns `500 Internal Server Error`.

### 5.2 Error Response Format
All errors return the `ErrorDetails` object as JSON:
```json
{
  "timestamp": "2026-05-17T10:30:00",
  "message": "Payment record not found for intent ID: pi_123",
  "details": "uri=/api/payments/webhook",
  "status": 404
}
```

## 6. Service Interactions

### 6.1 Order Service Interaction
The Payment Service acts as a client to the **Order Service** using Feign.
- **Target Service:** `ORDER-SERVICE`
- **Endpoint Called:** `PUT /api/internal/orders/{orderId}/payment-status`
- **Trigger:**
    - When a webhook confirms payment success (`payment_intent.succeeded`).
    - When a webhook confirms payment failure (`payment_intent.payment_failed`).
    - When a payment is manually canceled.

### 6.2 Stripe Interaction
- **SDK:** Stripe Java SDK.
- **Operations:**
    - Creating `PaymentIntent`.
    - Retrieving `PaymentIntent`.
    - Canceling `PaymentIntent`.
    - Validating and processing Webhook events.

- **App Name:** `payment-service`

- **Context Path:** `/payment-service`
- **Database:** MySQL (`jdbc:mysql://localhost:3306/ecommerce`)
